# Бенчмарк инференса на GX10 и RTX 4090

Дата: 2026-09-28

## Результат

Selectel RTX 4090 лучше подходит для инференса SAM3 и ShieldGemma.
RTX 4090 также быстрее для модели SigLIP2 fixed-512.
Оба хоста показывают близкую производительность SigLIP2 NaFlex с 256 патчами при одном запросе.
GX10 быстрее выполняет сканирование QR-кодов на CPU.

При параллелизме 8 RTX 4090 показывает следующую пропускную способность относительно GX10:

- SAM3: в 2,14 раза выше.
- ShieldGemma: в 2,06 раза выше.
- SigLIP2 fixed-512: в 1,43 раза выше.
- SigLIP2 NaFlex с 256 патчами: в 1,36 раза выше.
- QR-сканер: 0,61 от пропускной способности GX10.

Все 640 измеренных запросов инференса завершились успешно.
Каждый хост обработал 320 измеренных запросов.
Каждый хост также обработал 10 запросов прогрева.

## Хосты

| Хост | Ускоритель | Память | Состояние до теста |
|---|---|---:|---|
| GX10 | NVIDIA GB10 | 128 GiB объединенной памяти | Доступно 80 GiB; загрузка GPU 0%; четыре производственных GPU-процесса находились в памяти |
| Selectel `kit` | NVIDIA GeForce RTX 4090 | 24 564 MiB VRAM и 31 GiB системной памяти | Свободно 24 081 MiB VRAM; доступно 30 GiB системной памяти; вычислительных процессов нет |

Оба хоста использовали PyTorch 2.11.0, CUDA 13.0 и Transformers 5.3.0.
Четыре файла исходного кода сервисов имели одинаковые значения SHA-256 на обоих хостах.
Тест использовал прямой сервис на `127.0.0.1:18090`.
Тест не включал сетевую задержку и задержку шлюза совместимости.

## Методика

Runner загружал только одну модель с ускорителем одновременно.
Runner останавливал каждую модель перед загрузкой следующей модели.
Runner не перезапускал и не выгружал модели общего шлюза GX10.

Каждая модель получила два последовательных запроса прогрева.
Каждый измеренный сценарий содержал 16 запросов.
Клиент использовал параллелизм 1, 2, 4 и 8.
Клиент измерял полную задержку HTTP на хосте модели.

Оба хоста получили одинаковые входные данные:

- Запрос QR-сканера использовал одно статическое изображение QR-кода.
- Остальные запросы использовали одно сгенерированное изображение бутылки размером 320 на 480 пикселей.
- Запрос SAM3 использовал текст `wine bottle`.
- Ответ SAM3 не содержал маски.
- Запрос ShieldGemma проверял политики `dangerous`, `sexual` и `violence`.
- Запросы SigLIP2 возвращали один JSON-вектор из 1 152 значений.
- Запрос SigLIP2 NaFlex использовал `max_num_patches=256`.

SAM3 использовал один worker.
Максимальный размер пакета SAM3 был равен четырем изображениям.
Время ожидания пакета SAM3 было равно 15 мс.
SAM3 использовал float16.
ShieldGemma использовал bfloat16.

## Интерпретация

ShieldGemma последовательно выполняет вычисления модели с помощью одной блокировки.
Пропускная способность не увеличилась при росте параллелизма клиента.
Дополнительный параллелизм увеличил только задержку в очереди.
Клиент SHOULD использовать параллелизм 1 для одного процесса ShieldGemma.

SAM3 объединяет параллельные запросы в пакеты размером до четырех изображений.
Пропускная способность GX10 увеличилась на 50% при переходе от параллелизма 1 к параллелизму 8.
Пропускная способность RTX 4090 увеличилась на 12% при переходе от параллелизма 1 к параллелизму 8.
Клиент SHOULD использовать параллелизм 4 для стабильной задержки SAM3.
Клиент MAY использовать параллелизм 8, если пропускная способность важнее задержки.

Сервисы SigLIP2 последовательно выполняют вычисление модели.
Они могут параллельно выполнять подготовку изображения и формирование ответа.
RTX 4090 достиг приблизительно 56 запросов в секунду для NaFlex.
RTX 4090 достиг приблизительно 51 запроса в секунду для fixed-512.

QR-сканер использует CPU.
GX10 показал лучший результат при параллелизме 4.
Хост Selectel показал лучший результат при параллелизме 2.

## Ограничения

Этот тест является бенчмарком развертывания.
Он не является изолированным аппаратным микробенчмарком.

Во время теста GX10 продолжал обслуживать производственные GPU-процессы.
Загрузка GPU перед тестом была равна 0%.
Тест не отслеживал пересечение с производственными запросами на протяжении всего запуска.
Это условие может увеличить разброс результатов GX10.

GX10 читал большинство снимков моделей из кэша моделей на NAS.
GX10 читал SAM3 из полного локального пользовательского кэша.
Хост Selectel читал все снимки моделей из локального хранилища.
Не используйте время запуска для прямого сравнения ускорителей.

Среда ускорителя GX10 использовала немного более старые версии FastAPI, Pillow и multipart.
Исходный код моделей, версия PyTorch, версия Transformers, тела запросов и точность вычислений были одинаковыми.

Первый изолированный запуск SAM3 на GX10 обнаружил неполный снимок в кэше NAS.
Runner не записал данные инференса из этого запуска.
Успешный запуск использовал полный снимок, который уже использует работающий сервис SAM3 на GX10.

## Воспроизведение

Используйте `scripts/benchmark.py` для измерения запущенного прямого сервиса.

```sh
.venv/bin/python scripts/benchmark.py \
  --base-url http://127.0.0.1:18090 \
  --model sam3 \
  --route-mode direct \
  --concurrency 1,2,4,8 \
  --requests 16 \
  --warmup 2
```

Используйте `scripts/run_benchmarks.py` для автоматического запуска и остановки CUDA-сервисов.
Runner требует пути к среде Python с CUDA и к каталогу установленных моделей.

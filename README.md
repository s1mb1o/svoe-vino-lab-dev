# «Своё Вино»: поиск вина по фотографии

Проект распознаёт вино по фотографии бутылки или этикетки. Пользователь получает
карточку вина и ссылку на каталог [vino-svoe.ru](https://vino-svoe.ru/).

Решение создано для задачи #10 от РСХБ.Цифра "Сканер российских вин с описанием на платформе Свое Вино". Репозиторий содержит:

- веб-интерфейс Web UI,
- Telegram-бота,
- MAX-бота,
- HTTP-матчер,
- локальные сервисы моделей,
- сервис для обработки наборов данных и проведения экспериментов.

Для организаторов и жюри хакатона (людей и LLM): [ASSESSMENT.md](ASSESSMENT.md) — карта возможностей проекта.
Для каждой возможности файл указывает код, тесты и другие доказательства.

Рекомендации вина к еде для задачи #28 работают в отдельном серверном сервисе [Dinner Lens](dinner-lens/README.md).
Его документация описывает фильтры, которые применяет код, подготовленные варианты,
поиск по эмбеддингам и API с аутентификацией.
Web UI подключается к Dinner Lens через `/dish` и маршруты `/api/dinner/*` на том же домене.
Задайте `NUXT_DINNER_LENS_ENDPOINT` и `NUXT_DINNER_LENS_API_TOKEN` на сервере Web UI.
Настройки и ограничения описаны в [инструкции по интеграции](webui/docs/dinner-lens.md).
Telegram-бот и MAX-бот пока не подключены к Dinner Lens.
Текущий JSON Dinner Lens охватывает 200 блюд и 120 резервных и промежуточных классов.
Исходный набор из 75 блюд и контрольный набор фотографий доступны отдельно.

## Что умеет система

- Принимает JPEG, PNG, WebP и HEIF (HEIC) через Web UI и HTTP API матчера (HEIC в рабочем окружении
  с 2026-10-18). MAX-бот и Telegram-бот этого репозитория переводят HEIC-файл в JPEG.
  Telegram-бот в рабочем окружении принимает фото и альбомы, но не HEIC-файлы.
- Android-приложение принимает JPEG, PNG, WebP и HEIF (HEIC) из галереи.
- Web UI показывает предупреждение 18+ и требует подтвердить возраст перед доступом.
- Возвращает один `slug` через `POST /v1/eval/predict`.
- Возвращает до 20 кандидатов через `POST /v1/match`.
- Использует SigLIP2 и индекс эмбеддингов из 2 094 вин.
- Проверяет фотографии Telegram через ShieldGemma 2 до записи на диск.
- Использует SAM3 для поиска бутылки и этикетки.
- Показывает варианты, если уверенность результата недостаточна.
- Предлагает продукты к вину по данным выбранного магазина «Глобус».
- Сохраняет воспроизводимые запуски контрольных проверок и техническую трассировку.

## Результаты

Для контрольной проверки организаторы предоставили тестовый набор из 100 фотографий. Контрольная сумма набора: d9da3ea97ebd2f348efbe56efaed637416cc86934e711b29535e747184fe57dc.

Эталонные ответы организаторы не предоставили. Команда самостоятельно составила `expected.jsonl` путём сопоставления базы ФРАП, каталога vino-svoe.ru, сайтов и Telegram-каналов производителей.

Решение получило 95/100 совпадений с нашим эталоном, включая допустимые альтернативные `wine_slug`. Это результат внутренней проверки команды, а не официальная оценка жюри.

Файл: `predictions.jsonl`

В отдельном диагностическом эксперименте ручная корректировка данных через интерфейс повысила результат до 97/100. Однако изменения были сделаны после выяснения правильных ответов. Такой результат отражает подстройку под известный тест и требует проверки на независимых данных. Поэтому эти изменения не включены в финальный результат: он остаётся 95/100.

## Последние инженерные измерения

Исследование поиска от 2026-10-20 показало **90.77% R@1** (2,696/2,970),
**99.83% R@5** и **100% R@10** на зафиксированном наборе положительных соответствий `my`.
Это метрики конфигурации R011 с SigLIP2 SO400M, собственным методом пулинга, осевыми
эталонными ракурсами и объединением признаков бутылки и этикетки. Исследование не использует повторное ранжирование.
См. [точные конфигурации и результаты](RETRIEVAL-ALGORITHMS-AND-RESULTS-20261020.md).

На выбранном сложном наборе `my-failed-2` лучший R@1 среди всех лимитов числа патчей
составляет **67.37%** (450/668). Лучший R@1 для p512 составляет **66.17%** (442/668).
Эти наборы использовали для выбора конфигураций при разработке. Это исследовательские результаты.
Они не описывают матчер с настройками по умолчанию или официальную оценку хакатона.

В более поздней [записи о выпуске Android 0.3.0](https://github.com/s1mb1o/svoe-vino-lab-dev/blob/6bd4abed8009296dec8cdde4e418103f610a74ba/android/docs/releases/0.3.0.md) указаны
**46.56% Top-1**, **84.58% Top-5** и **89.67% Top-10** на сложном наборе с тем же именем.
Полный повтор 668 запросов на Pixel 8 завершился без ошибок. Медиана времени составила 1,372 мс.
Выпуск использует Base NaFlex p512 с DIS-768 и собственным методом пулинга.
Запись не содержит результата проверки качества на полном наборе `my`.
Более ранний отдельный эксперимент на двух GPU достиг **72.29% Top-1** на полном наборе `my`.
Соответствующая контрольная конфигурация с полным изображением показала **69.09%**. Эксперимент потребовал больше времени и памяти.
Исходный код Android 0.3.0 и запись о выпуске находятся в `origin/main` в указанном коммите.
Эта правка документации не добавляет реализацию этого выпуска в данную копию проекта.

Размеры наборов данных, полные строки метрик, условия измерения времени,
отрицательные примеры и ссылки на источники приведены в [BENCHMARKS.md](BENCHMARKS.md).

## Предыдущие инженерные измерения

Снимок от 2026-09-27 содержит 2,228 строк запросов: 1,644 положительные строки и 584 отрицательных ограничения.
Он содержит 1,851 уникальную контрольную сумму изображения.
Конфигурация по умолчанию `siglip2-p512-as-is`, сохранённая в репозитории, показала **74.15% R@1** и **92.94% R@5**
на этом снимке. Эта конфигурация отличается от более новых исследовательских конфигураций.

Зафиксированный запуск `cascade-p512-rot5` через API ранжированных результатов показал **90.48% R@1** и **100% R@5**
на 63 положительных и 21 отрицательной фотографии организаторов. Запуск использовал разметку команды и не ограничивал время запроса.
Более поздний запуск VLM в формате FP8 на RTX 4090 показал **93.65% R@1** (59/63 положительных примеров)
с ограничением времени, которое задаёт скрипт проверки. Все 84 запроса завершились без ошибок. Медиана времени составила 1,353 мс.
См. [запись измерения](workbench/ResearchLog.md).
Эти запуски используют разное оборудование и разные настройки запросов.

Лидер лабораторных экспериментов на 2026-09-27, `barcode-rerank-siglip2-512-crop`, показал
**84.67% R@1** и **97.02% R@5** на более раннем снимке из 1,644 положительных примеров.
Более новый исследовательский набор содержит 2,970 положительных соответствий.
Разница между 84.67% и 90.77% не является результатом контролируемого сравнения на одном фиксированном тестовом наборе.
Серверная реализация `cascade` поддерживает считывание кодов, сегментацию и повторное ранжирование.
Конфигурация по умолчанию `siglip2-p512-as-is` не включает эти этапы.

## Исследование поиска без повторного ранжирования

Документ [«Алгоритмы поиска и результаты контрольных проверок, 20 октября 2026 года»](RETRIEVAL-ALGORITHMS-AND-RESULTS-20261020.md)
описывает отдельное исследование SigLIP2 SO400M NaFlex. Оно сравнивает **353,188 уникальных
конфигураций поиска на каждом зафиксированном тестовом наборе** `my` и `my-failed-2`.
Документ задаёт 39 профилей пулинга, 42 правила объединения признаков, выравнивание изображений запросов,
поиск по этикетке, синтетические осевые ракурсы бутылки, отступы при обрезке, лимиты числа патчей
и агрегирование оценок эталонных изображений. Документ содержит формулы, точные параметры,
сравнения с базовыми конфигурациями, таблицы пяти лучших результатов, лучшие варианты p512 и 53 точные конфигурации результатов.

На выбранном сложном наборе `my-failed-2` лучший R@1 вырос с **44.01% до 67.37%**.
Лучший R@1 для p512 составляет **66.17%**. Это исследовательские результаты на наборе для разработки.
Они не являются оценками рабочего матчера или официальными оценками хакатона.
Документ сохраняет отдельно результаты GX10 и неполные результаты RTX4090. [Переносимый исследовательский пакет](research/retrieval-20261020/README.md)
содержит снимки исходного кода, зафиксированные спецификации, краткие сводки контрольных проверок
и автономный скрипт проверки. Выполните `python3 research/retrieval-20261020/verify.py`, чтобы проверить
пакет без весов моделей и доступа к сети. Полные наборы контрольных изображений, маски,
допустимые ответы и полные базы результатов не входят в пакет. См. F-112 в
[ASSESSMENT.md](ASSESSMENT.md).

## Быстрый запуск интерфейса

```bash
cd webui
npm ci
npm run dev
```

Откройте [http://127.0.0.1:8153](http://127.0.0.1:8153).
По умолчанию Web UI явно работает в режиме имитации. Для реального распознавания нужны
матчер и эндпоинт модели. Полная инструкция находится в [SETUP.md](SETUP.md).

## Компоненты

| Каталог | Назначение |
| --- | --- |
| `webui/` | Web UI на Nuxt, маршрут API проверки и рекомендации еды. |
| `mcp/` | Инструменты MCP только для чтения: карточки каталога, поиск, сравнение, демонстрация товарной линейки и утверждённые метаданные аудио. |
| `account/` | Сервис аккаунтов «Винный дневник»: вход по коду из письма и Яндекс ID, привязка MAX и Telegram (без входа через Telegram). |
| `telegram-bot/` | Бот [@ChtoZaVinoBot](https://t.me/ChtoZaVinoBot), модерация и очередь. |
| `max-bot/` | Бот MAX «Что за вино?» [@se14697933_bot](https://max.ru/se14697933_bot) с той же функциональностью. |
| `im-core/` | Общее ядро обработки обоих ботов (пакет `chto_za_vino_core`). |
| `shelf-lens/` | Android-приложение «Полка вина»: видео полки, поиск бутылок на телефоне, распознавание через матчер, рамки и рейтинг поверх камеры, планограмма. |
| `matcher/` | Матчер на FastAPI с Top-1 и API ранжированных результатов. |
| `bootstrap/` | Локальные эндпоинты SigLIP2, SAM3, ShieldGemma 2 и сканер QR-кодов. |
| `matcher-inspector/` | Просмотр запросов и комплектов эмбеддингов без возможности изменения. |
| `workbench/` | Данные, индексы, эксперименты, контрольные проверки и сборка комплектов данных. |
| `eval/` | Скрипт проверки организаторов и три контрольных фотографии. |

## Ограничения

- Веса моделей не хранятся в Git. Комплект данных для автономного матчера хранится в Git:
  `matcher/data/gx10-siglip2-so400m-patch16-naflex-p512/`.
- Реальный запуск требует эндпоинт SigLIP2 и комплект данных.
- Режим распознавания полки в Web UI выключен по умолчанию.
- Лаборатория и инспектор не имеют публичной аутентификации. Их нельзя публиковать в интернете.
- Контрольная проверка является внутренней инженерной оценкой. Это не официальная оценка хакатона.

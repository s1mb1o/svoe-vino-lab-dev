Migrationspipeline/labdb.py applies each file pipeline/schema/NNN_<name>.sql one time, in number order, with one transaction for each file. PRAGMA user_version holds the number of the last applied file. The code refuses a gap in the numbers. A change is a new file with the next number. Do not edit an applied file.

RebuildsTo change a constraint or to remove a column, a file builds the table again: a new table, a copy of the rows, DROP, RENAME. Files 004, 007, 010, 012, 014, 016, and 017 do this. labdb.migrate runs each file with the foreign keys off, and PRAGMA foreign_key_check checks each link before the COMMIT. A rebuild of wine_catalog drops its two triggers, so the file MUST create them again.

ImagesThe store is images/ in the directory of the database file. The same bytes are stored one time, in the folder of the type that stored them first: main, patched (main_patched), additional (full_*, label_*), testset. A new cut goes to cropped. A reader MUST use main_patched instead of main when a wine has both.

ValuesThe columns created_at and modified_at hold UTC text YYYY-MM-DDTHH:MM:SSZ; a GLOB check keeps the form. A TEXT column refuses '' through a CHECK or its foreign key. Exceptions: website_refusal.field, website_refusal.website_value, test_excluded.reason, test_excluded.ts. The code does not delete a row of wine_catalog: Removed and Disabled are states.

Test setsThe labels stay in git, in dataset/<set>/review-labels.json. pipeline/import_testset.py copies them here, read-only. Each import makes the rows of a set equal to the files again. The slugs of the test-set tables and of website_refusal have no foreign key (≈).

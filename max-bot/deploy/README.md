# Развёртывание MAX-бота «Что за вино?»

Инструкция подходит для любого Linux-сервера с Docker. Она не привязана к конкретной установке.
Примеры файлов:

- [compose.example.yaml](compose.example.yaml) — файл Docker Compose;
- [max-bot.env.example](max-bot.env.example) — шаблон файла окружения.

В примерах сервер — `user@server`, каталог установки — `/opt/max-bot`. Замените их на свои.

## Как устроено развёртывание

- Один образ Docker. Его собирают из закоммиченной ревизии. Образ не содержит секретов.
- Два контейнера из этого образа:
  - `bot` получает обновления MAX и обслуживает HTTP API распознавания (порт контейнера `8080`);
  - `admin` обслуживает административный веб-интерфейс. Он слушает только loopback сервера.
- Файл окружения `config/max-bot.env` хранит секреты и адреса сервисов. Режим файла — `0600`.
- Каталог данных `data/` хранит базу SQLite, принятые фотографии, карантин и артефакты.
  Владелец каталога — uid 1000: контейнеры работают от uid 1000.

## Требования

- Linux-сервер с Docker Engine и Docker Compose v2 (`docker compose version`). Compose должен
  поддерживать `format: raw` в `env_file`.
- Исходящий HTTPS к `platform-api2.max.ru` и к хостам медиафайлов MAX. Корневой сертификат
  Минцифры уже есть в образе. Добавлять его на сервер не нужно.
- Сервисы, которые вызывает бот:
  - шлюз моделей с ShieldGemma 2 (`/upstream/shieldgemma-2-4b-it/classify`) и SAM3
    (`/upstream/sam3`);
  - matcher с `POST /v1/match`.
- Токен бота MAX и MAX user ID администратора. Как их получить, описано в разделе «Первая
  настройка: токен и ID администратора» файла [../README.md](../README.md).
- Свободные порты сервера. В примере: `28004` — API распознавания, `28005` — административный
  интерфейс, `28006` — вебхук (только в режиме вебхука).
- Пользователь сервера с uid 1000, который может запускать Docker (например, в группе `docker`).
  Контейнеры работают от uid 1000. Ниже этот пользователь — `user`. Шаги установки после
  создания каталогов выполняет он.

Один токен обслуживает один экземпляр бота. Перед запуском остановите другие экземпляры с этим
токеном, например локальный запуск: экземпляры забирают обновления друг у друга.

## Сборка образа

Соберите образ на машине с клоном репозитория, в корне репозитория. Образу нужен общий пакет
`im-core/`, поэтому контекст сборки — корень репозитория:

```bash
REV=$(git rev-parse HEAD)   # или другая закоммиченная ревизия
git archive "$REV" im-core max-bot | docker build -f max-bot/Dockerfile \
    --build-arg REVISION="$REV" -t "svoe-vino-lab-max-bot:$REV" -
```

`git archive` берёт файлы коммита, а не рабочего каталога. Поэтому в образ не попадают
незакоммиченные изменения и локальные файлы с секретами.

Если у сервера нет клона репозитория, соберите образ на сервере через SSH:

```bash
git archive "$REV" im-core max-bot | ssh user@server \
    "docker build -f max-bot/Dockerfile --build-arg REVISION=$REV -t svoe-vino-lab-max-bot:$REV -"
```

## Первая установка

1. Создайте каталоги на сервере. Каталог `/opt` обычно принадлежит root, поэтому команды
   используют `sudo` и делают владельцем uid 1000:

   ```bash
   ROOT=/opt/max-bot
   sudo install -d -o 1000 -g 1000 -m 0750 "$ROOT"
   sudo install -d -o 1000 -g 1000 -m 0700 "$ROOT/data" "$ROOT/config"
   ```

   Если родительский каталог уже доступен на запись пользователю `user`, `sudo` не нужен.

2. Скопируйте пример Compose и шаблон окружения. Выполните команды на своей машине, в каталоге
   `max-bot/deploy/` репозитория:

   ```bash
   scp compose.example.yaml user@server:/opt/max-bot/compose.yaml
   ssh user@server 'umask 077; cat > /opt/max-bot/config/max-bot.env' < max-bot.env.example
   ```

3. Заполните `config/max-bot.env` (раздел «Файл окружения»). Токен бота запишите командой из
   раздела «Первая настройка» файла [../README.md](../README.md). Команда не выводит токен на
   экран.

4. Проверьте права на сервере:

   ```bash
   stat -c '%a %u' /opt/max-bot/config/max-bot.env   # 600 1000
   stat -c '%a %u' /opt/max-bot/data                 # 700 1000
   ```

5. Укажите образ и запустите оба контейнера:

   ```bash
   cd /opt/max-bot
   echo "MAX_BOT_IMAGE=svoe-vino-lab-max-bot:<ревизия>" > .env
   docker compose up -d
   docker compose ps
   ```

При первом запуске бот создаёт `data/bot.sqlite3` и устанавливает меню команд
(`BOT_SYNC_PROFILE=true`). Затем он проверяет, что подписка на вебхук не активна, и начинает
long polling.

## Файл окружения

Compose читает `config/max-bot.env` в формате `raw`: значение берётся как есть. Не берите
значения в кавычки и не используйте `$NAME`.

| Переменная | Что задать |
|---|---|
| `MAX_BOT_TOKEN` | Токен бота. Секрет |
| `BOT_ADMIN_USER_ID` | MAX user ID администратора (число). Не секрет |
| `BOT_HTTP_API_TOKEN` | Случайное значение не короче 32 символов. Секрет |
| `BOT_ADMIN_WEB_PASSWORD` | Случайное значение не короче 32 символов. Секрет |
| `MODERATION_ENDPOINT`, `SAM3_ENDPOINT` | Адреса ShieldGemma 2 и SAM3 в шлюзе моделей |
| `MATCHER_ENDPOINT` | Адрес `/v1/match` сервиса matcher |
| `BOT_HTTP_API_ALLOWED_NETWORKS` | Сети клиентов API: CIDR через запятую |

- Создавайте каждое случайное значение отдельно, например командой `openssl rand -hex 32`.
- `MAX_BOT_TOKEN`, `BOT_HTTP_API_TOKEN` и `MAX_WEBHOOK_SECRET` ДОЛЖНЫ (MUST) различаться.
- Не передавайте секрет в аргументах команды: история оболочки сохраняет его.
- В контейнере `127.0.0.1` — это сам контейнер. В адресах сервисов указывайте адрес, доступный
  из контейнера, например адрес сервера с моделями в локальной сети.
- `BOT_ENVIRONMENT=production` требует включённой модерации. Бот удаляет данные завершённых
  запросов через 30 дней (`BOT_DATA_RETENTION_DAYS=30`).

Остальные переменные описаны в шаблоне и в разделе «Конфигурация» файла
[../README.md](../README.md).

## Сеть и порты

- API распознавания слушает порт контейнера `8080`. Пример публикует его на порту `28004` всех
  интерфейсов сервера. Доступ ограничивают bearer-токен `BOT_HTTP_API_TOKEN` и список сетей
  `BOT_HTTP_API_ALLOWED_NETWORKS`.
- Клиенты обращаются к API по адресу сервера в локальной сети. Запрос с самого сервера на
  `127.0.0.1` может прийти в контейнер с адреса сети Docker, и API его отклонит. Используйте
  адрес сервера в локальной сети или добавьте сеть Docker в список.
- Контейнер `admin` работает в сети сервера и слушает только `127.0.0.1:28005`. Откройте
  интерфейс через SSH-туннель:

  ```bash
  ssh -N -L 28005:127.0.0.1:28005 user@server
  # затем откройте http://127.0.0.1:28005/ в браузере
  ```

- Публикуйте административный интерфейс в сеть только через TLS-прокси
  (`BOT_ADMIN_WEB_BEHIND_TLS_PROXY=true`).

## Проверка

1. Оба контейнера в состоянии `healthy`: `docker compose ps`.
2. Журнал содержит `MAX bot connected bot_user_id=...` и `MAX bot and HTTP API started`. Токена
   в журнале нет: `docker compose logs --tail 50 bot`.
3. API живо и готово:

   ```bash
   curl -fsS http://<адрес-сервера>:28004/healthz
   curl -fsS http://<адрес-сервера>:28004/readyz
   ```

   `/readyz` показывает готовность базы, очереди, модерации, SAM3 и matcher.
4. В MAX откройте бота, нажмите «Начать», подтвердите возраст и отправьте фотографию вина.
   Полная ручная проверка — [../SMOKE_TESTS.md](../SMOKE_TESTS.md).
5. Автоматическая проверка сервиса — `scripts/smoke.py`. Скопируйте на сервер
   `max-bot/scripts/smoke.py` в `checks/scripts/` и `max-bot/tests/data/smoke-wine.webp` в
   `checks/tests/data/`. Затем запустите скрипт в образе бота:

   ```bash
   cd /opt/max-bot
   docker run --rm --network host --read-only --cap-drop ALL \
     --security-opt no-new-privileges:true --tmpfs /tmp \
     --env-file config/max-bot.env --volume "$PWD/checks:/checks:ro" \
     --entrypoint python "$(sed -n 's/^MAX_BOT_IMAGE=//p' .env)" /checks/scripts/smoke.py \
     --api-url http://<адрес-сервера>:28004 --admin-url http://127.0.0.1:28005 --check-max
   ```

   Скрипт не выводит секреты и не читает обновления MAX. Каждый запуск создаёт один
   неверный запрос и один запрос распознавания.

## Обновление и откат

- Обновление: соберите новую ревизию, запишите её образ в `.env` и выполните
  `docker compose up -d`. Compose пересоздаёт оба контейнера. Бот завершает или восстанавливает
  задания очереди и продолжает long polling с сохранённой позиции. Затем выполните проверку.
- Откат: запишите в `.env` имя предыдущего образа и выполните `docker compose up -d`. Храните
  предыдущий образ, пока новый не прошёл проверку.
- Изменения `config/max-bot.env` применяются после `docker compose up -d`.
  `docker compose restart` не перечитывает файл.

## Эксплуатация

- Журнал: `docker compose logs -f bot`. Docker хранит 5 файлов по 10 МБ для каждого контейнера.
- Остановка: `docker compose stop`. Бот получает SIGTERM и завершается корректно.
- Замена токена: обновите токен на business.max.ru, запишите его в `config/max-bot.env` и
  выполните `docker compose up -d`. Старый токен перестаёт работать.
- Резервная копия: остановите бота или выполните `sqlite3 data/bot.sqlite3 ".backup ..."`, затем
  скопируйте `data/`. Каталог содержит фотографии пользователей. Храните копию с той же защитой.
- Хранение: бот удаляет данные завершённых запросов через 30 дней, при запуске и раз в сутки.
- Удаление одного запроса по жалобе: кнопка «Удалить запрос» в административном интерфейсе
  (раздел «Удаление запроса по жалобе» файла [../README.md](../README.md)).

### Удаление всех данных одного пользователя

Команда отказывает, если у пользователя есть активный запрос (`received`, `queued`,
`processing` или `retry_requested`).

1. Посчитайте активные запросы пользователя. Продолжайте, только если результат `0`:

   ```bash
   docker compose run --rm --no-deps -T bot python - USER_ID <<'PY'
   import sqlite3, sys
   active = ("received", "queued", "processing", "retry_requested")
   print(sqlite3.connect("/data/bot.sqlite3").execute(
       "SELECT COUNT(*) FROM requests WHERE user_id = ? AND status IN (?, ?, ?, ?)",
       (int(sys.argv[1]), *active),
   ).fetchone()[0])
   PY
   ```

2. Остановите бота, удалите данные и запустите бота:

   ```bash
   docker compose stop bot
   docker compose run --rm --no-deps bot chto-za-vino-max-delete-user USER_ID --confirm
   docker compose start bot
   ```

Если команда сообщает об активных запросах, запустите бота, дождитесь конца обработки и
повторите с шага 1.

## Переход на вебхук

MAX рекомендует вебхук для production. Для вебхука нужно публичное HTTPS-имя на порту 443 с
сертификатом доверенного центра или сертификатом Минцифры и TLS-прокси до сервера.

1. В `compose.yaml` раскомментируйте порт `127.0.0.1:28006:8081` сервиса `bot`. Направьте
   TLS-прокси на этот порт.
2. Задайте `updates.mode: webhook` в `config.yaml`. Образ содержит `/app/config.yaml`:
   пересоберите образ или подключите другой файл и укажите его в `BOT_CONFIG`. В
   `config/max-bot.env` задайте `MAX_WEBHOOK_URL` и отдельное случайное значение
   `MAX_WEBHOOK_SECRET` (от 32 до 256 символов из `A-Za-z0-9_-`).
3. Выполните `docker compose up -d`. Бот подписывает адрес при запуске.
4. Чтобы вернуться к long polling, сначала удалите подписку (`DELETE /subscriptions?url=...`).
   Бот не запускает long polling, пока подписка активна.

## Безопасность

- Файл окружения имеет режим `0600`. Образ и журналы не содержат секретов. Не храните файл
  окружения в этом репозитории.
- Административный интерфейс слушает только loopback сервера.
- API распознавания принимает только сети из `BOT_HTTP_API_ALLOWED_NETWORKS` и требует
  bearer-токен.
- Оба контейнера работают от uid 1000, с корневой файловой системой только для чтения, без
  capabilities и с `no-new-privileges`. Запись разрешена только в `/data` и в tmpfs `/tmp`.

# «Полка вина»: сканирование винной полки

Android-приложение проходит камерой вдоль полки, находит каждую бутылку один раз,
распознаёт вино через API «Своё Вино» и строит планограмму полки. Карточка каждого
вина ведёт в каталог [vino-svoe.ru](https://vino-svoe.ru/).

Проект — часть решения задачи #10 от РСХБ.Цифра «Сканер российских вин с описанием на
платформе Свое Вино». Распознавание одной бутылки делает основной репозиторий
`svoe-vino-lab-dev` (API `/v1/match`); этот репозиторий отвечает за полку целиком:
- Android-приложение «Полка вина» (`android/`);
- ядро трекера на C++ (`cpp/`), общее для телефона и проверок на компьютере;
- исследовательский прототип на Python (`src/shelfreid/`) и скрипты экспериментов.

## Что умеет система

- Находит бутылки в кадре детектором на телефоне (YOLOX-s, ONNX Runtime + NNAPI).
- Держит карту полки: каждая физическая бутылка получает один номер, в том числе после
  ухода камеры и возврата, паузы или сворачивания приложения.
- Отправляет на распознавание лучшую вырезку каждой бутылки, один запрос на бутылку.
- Показывает состояние рамкой: серая — бутылка найдена, жёлтая с песочными часами — ждёт
  ответа сервера, зелёная — вино распознано, внизу рамки звёзды рейтинга.
- Показывает список найденных вин с фильтрами по рейтингу, типу, сахару и региону.
- Строит планограмму: полки снизу вверх, фейсинги с изображениями вин, блоки одного вина;
  её можно приблизить, распечатать и отправить.
- APK содержит сборки для 64- и 32-битных ARM-телефонов (arm64-v8a, armeabi-v7a), Android 10 и новее.

## Как это работает

```
камера ─► детектор (каждый 3-й кадр) ─► трекер ─► карта полки ─► планограмма
              │                            │            │
   движение кадра (каждый кадр)    быстрый контур:   очередь вырезок ─► /v1/match ─► карточка вина
                                   оптический поток   (лучшая за 1 с,     (до 4 запросов   + рейтинг
                                   медленный контур:   бутылки в кадре    одновременно)    с vino-svoe.ru
                                   SIFT, граф поз      первыми)
```

**Идентичность бутылки — её место на полке, а не внешний вид.** Соседние бутылки одного
вина одинаковы, отличить их можно только по положению. Кадры связываются гомографией
лицевой плоскости полки, и бутылки нового кадра сравниваются с картой по месту.

**Трекер работает в два контура**, как того требует телефон:
- быстрый, на каждом обработанном кадре: оптический поток по бутылкам и оценка движения
  всего кадра, рамки следуют за картинкой без задержки;
- медленный, в отдельном потоке: SIFT, привязка к ключевым кадрам, граф поз, замыкание
  петли, проверка номеров по этикеткам.

**Защиты карты:**
- привязка, сдвигающая камеру на целую бутылку, на ряду одинаковых бутылок отбрасывается
  (иначе номера «сползают» на соседей);
- пока привязки нет, рамки ничего не добавляют в карту: отдельных кусков карты не бывает,
  планограмма строится по одной карте; для другой полки — «Новая полка» в меню;
- после паузы камеры трекер сразу ищет себя на карте и продолжает её;
- бутылки второго ряда в щели между передними и бутылки, срезанные нижним краем кадра
  (без этикетки), отбрасываются.

**Распознавание.** Для каждой бутылки, занимающей не меньше 19% высоты кадра (с этого
размера сервер уверенно узнаёт вино), собираются вырезки с первой секунды; на сервер
уходит лучшая по размеру и резкости. Очередь
разбирается в фоне всегда, в том числе пока открыто меню, список или планограмма. Рейтинг
и крепость вина приложение берёт из открытых данных сайта vino-svoe.ru: в ответе API их нет.

**Планограмма.** Полки — ряды карты; расстояния между бутылками берутся не из карты, а из
того, как бутылки стоят относительно друг друга в кадрах (метод наименьших квадратов), —
так полки выравниваются между собой и ошибки карты не накапливаются.

Подробно — в [docs/design.md](docs/design.md).

## Результаты

Внутренние проверки на видео с телефона:

| Проверка | Результат |
| --- | --- |
| Детектор на телефоне (Xiaomi, MediaTek MT6991, NNAPI FP16) | 31–40 мс на кадр |
| Трекер на телефоне | быстрый контур 29–33 мс, медленный 340–530 мс |
| Полка из 28 бутылок вплотную, ряд одинаковых бутылок (видео 191144) | 28 из 28 на планограмме |
| Верхняя полка того же видео | 21 из 21 |
| Одна бутылка, три ухода камеры и возврата (видео 103509) | один номер, без дублей |
| Та же секция, снятая дважды с разницей 5 часов (видео 135357 и 191144) | полки совпали; единственное отличие — бутылка, которой за это время не стало на полке |
| API: пропускная способность | 1,6 вырезки/с при 4 запросах (1,0 при 2) |
| API: размер вырезки | от ~400 px по высоте сервер узнаёт производителя |

## Сборка и запуск

Нужны Android SDK и JDK 17 (их ставит Android Studio). NDK и CMake нужных версий Gradle
скачает сам. Модель детектора лежит в репозитории (`android/app/src/main/assets`).
Нативные зависимости (OpenCV 5.0.0, ONNX Runtime 1.22.0, Eigen 5.0.1, nlohmann/json
3.12.0) скачивает в `third_party/` скрипт, он же пишет `android/local.properties`:

```bash
android/setup.sh
cd android
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Пароль API распознавания в репозиторий не кладётся. Файл `api_password.txt` (одна строка —
пароль) кладётся в папку приложения на телефоне после первого запуска:

```bash
adb push api_password.txt /sdcard/Android/data/ru.svoevino.shelfreid/files/
```

Пароль нужен только для распознавания: поиск бутылок и карта работают и без него.

**Режим отладки** включается долгим нажатием на название на главном экране. В нём видны
номера бутылок, статистика трекера, таблица бутылок, и проигрываются видео `*.mp4` из
папки приложения — как будто их снимает камера. Состояние трекера и очереди распознавания
приложение пишет в журнал телефона (`adb logcat -s shelfreid Recognizer`).

## Исследовательская часть

Прототип на Python и инструменты проверки ядра на видео:

```bash
uv sync
uv run pytest -q

# Детекции видео моделью телефона (кэш для replay).
uv run --extra detect python scripts/detect_onnx.py \
    android/app/src/main/assets/bottle_yoloxs.onnx video VIDEO.mp4 --out dets.jsonl

# Ядро C++ на видео, как на телефоне: номера бутылок, карта, планограмма
# (OpenCV, Eigen и nlohmann-json для сборки на компьютере — из Homebrew).
cmake -S cpp -B cpp/build -G Ninja && ninja -C cpp/build replay
cpp/build/replay VIDEO.mp4 dets.jsonl rt:3 track.jsonl --every 3 --keep-steps 1 --hints 1 \
    --max-side 960 --max-features 2500 --map map.json --planogram planogram.json

# Распознать бутылки планограммы через API и нарисовать её (пароль в CHTOZAVINO_API_PASSWORD).
uv run python scripts/planogram.py label VIDEO.mp4 track.jsonl planogram.json out/
uv run python scripts/planogram.py render planogram.json planogram.png --labels out/labels.json
```

Трассировка ядра: `SHELFREID_TRACE=1` (состояние трекера по шагам, переименования
бутылок), `SHELFREID_TRACE_FRAMES=FROM-TO` (как каждая рамка получила номер),
`SHELFREID_TRACE_REG=1` (каждая привязка к ключевому кадру), `--interrupt FRAME` в replay
(разрыв съёмки, как после паузы камеры).

## Компоненты

| Каталог | Назначение |
| --- | --- |
| `android/` | Приложение «Полка вина»: камера, экраны, распознавание, планограмма; `setup.sh` — зависимости сборки. |
| `cpp/` | Ядро трекера (два контура, граф поз, планограмма) и `replay` — прогон ядра на видео. |
| `src/shelfreid/` | Прототип на Python: связывание кадров, поток, граф поз, серия снимков. |
| `scripts/` | Детектор, разметка, проверка API, нагрузочный тест, планограмма. |
| `train/` | Обучение детектора бутылок (YOLO, YOLOX). |
| `tests/` | Тесты прототипа. |
| `docs/` | Дизайн и история решений. |

Данные (видео, кадры, фото) лежат в `data/`, результаты — в `out/`, скачанные
зависимости — в `third_party/`. Эти папки не попадают в git.

**Priority:** P2 · **Effort:** S · **Status:** VERIFIED

## Problem

The SEO tests (`webui/tests/seo.test.ts`, `webui/tests/sitemap.test.ts`) check source strings only. They cannot see edge headers (SEO-005) or a release gap (SEO-012). `webui/scripts/check-contract.mjs` also has stale assertions:

- [`webui/scripts/check-contract.mjs:40–41`](https://github.com/s1mb1o/svoe-vino-lab-dev/blob/cd8b063ecd000872567e543407b11926b45b3d37/webui/scripts/check-contract.mjs#L40-L41) expect «Проверяем подтверждение возраста» and `age-loading`. The current age gate has neither.
- [`webui/scripts/check-contract.mjs:79–82`](https://github.com/s1mb1o/svoe-vino-lab-dev/blob/cd8b063ecd000872567e543407b11926b45b3d37/webui/scripts/check-contract.mjs#L79-L82) expect 302 for `/wines/<slug>`. The route and `tests/seo.test.ts` use 308.

`check-contract.mjs` requires mock mode and sends evaluator images, so it must not run against production.

## Fix

1. Fix the two stale assertions.
2. Add a read-only post-deploy check (curl only, no uploads, no credentials), for example `webui/scripts/check-seo-http.sh`:

```sh
#!/bin/sh
set -eu
base="${1:-https://chtozavino.ru}"; fail=0
for path in / /shelf /dish /lineup /android /iphone /telegram-bot /max-bot /ideas /game /crocodile /presentation /sitemap /terms /privacy /contacts; do
  html=$(curl -s -A 'Mozilla/5.0 (compatible; Googlebot/2.1)' "$base$path")
  code=$(curl -s -o /dev/null -w '%{http_code}' "$base$path")
  want="https://chtozavino.ru${path%/}"; [ "$path" = / ] && want="https://chtozavino.ru/"
  canon=$(printf '%s' "$html" | grep -o '<link rel="canonical" href="[^"]*"' | sed 's/.*href="//; s/"$//')
  ogurl=$(printf '%s' "$html" | grep -o '<meta property="og:url" content="[^"]*"' | sed 's/.*content="//; s/"$//')
  [ "$code" = 200 ] || { echo "FAIL $path status $code"; fail=1; }
  [ "$canon" = "$want" ] || { echo "FAIL $path canonical $canon"; fail=1; }
  [ "$ogurl" = "$want" ] || { echo "FAIL $path og:url $ogurl"; fail=1; }
  printf '%s' "$html" | grep -q 'name="robots" content="noindex' && { echo "FAIL $path noindex meta"; fail=1; }
done
for loc in $(curl -s "$base/sitemap.xml" | grep -o '<loc>[^<]*' | sed 's/<loc>//'); do
  hdr=$(curl -s -o /dev/null -D - "$loc")
  printf '%s' "$hdr" | head -1 | grep -q ' 200' || { echo "FAIL sitemap $loc status"; fail=1; }
  printf '%s' "$hdr" | grep -qi '^x-robots-tag:.*noindex' && { echo "FAIL sitemap $loc noindex header"; fail=1; }
done
exit $fail
```

On production today it reports `/dish og:url` (SEO-008) and `/presentation` noindex header (SEO-005).

3. Add it to `webui/SMOKE_TESTS.md` as a release step.

## Verify

The script exits 0 after SEO-008 and SEO-005; a seeded `noindex` on a sitemap URL makes it fail.

SEO-005: /presentation is in sitemap.xml but the edge sends X-Robots-Tag: noindex
<!-- labels: bug -->

**Priority:** P2 · **Effort:** S · **Status:** VERIFIED (edge layer LIKELY)

## Problem

`sitemap.xml` and the HTML site map list `/presentation`, but the page response has `X-Robots-Tag: noindex, nofollow, noarchive`. A sitemap must list only indexable URLs. The owner decision in #77 (2026-10-20) is: presentation pages are public, and search engines may index the site.

## Evidence

```
$ curl -sI https://chtozavino.ru/presentation | grep -i -E '^(HTTP|x-robots-tag)'
HTTP/2 200
x-robots-tag: noindex, nofollow, noarchive
```

The page itself has no robots meta tag, and `nuxt.config.ts` has no rule for `/presentation`. The header comes from the edge (Caddy `/presentation*` route that #77 keeps «with its other headers»). `/presentations/*.pdf` and `/presentation/video.mp4` have the same header.

## Where

- [`webui/public/sitemap.xml:30–32`](https://github.com/s1mb1o/svoe-vino-lab-dev/blob/cd8b063ecd000872567e543407b11926b45b3d37/webui/public/sitemap.xml#L30-L32), [`webui/app/data/sitemap.ts:48`](https://github.com/s1mb1o/svoe-vino-lab-dev/blob/cd8b063ecd000872567e543407b11926b45b3d37/webui/app/data/sitemap.ts#L48)
- Edge: Caddy `/presentation*` and `/presentations*` routes (deploy repository).

## Fix (owner chooses)

1. **Recommended (matches #77):** remove `X-Robots-Tag` for the HTML page `/presentation` at the edge. Keep it for the PDF/PPTX/video files if they must stay out of search.
2. Or keep `noindex` and remove `/presentation` from `public/sitemap.xml`. Then `webui/tests/sitemap.test.ts` must allow a page in the HTML site map that is not in the XML sitemap.

## Verify

Every `<loc>` in `sitemap.xml` returns 200 without `noindex` in the header or meta (post-deploy check, SEO-013).

SEO-022: /favicon.ico returns 78 bytes of text with Content-Type image/x-icon
<!-- labels: bug -->

**Priority:** P2 · **Effort:** S · **Status:** VERIFIED (edge layer LIKELY)

## Problem

`/favicon.ico` is not a valid icon. Tools and crawlers that read `/favicon.ico` directly get a broken file.

## Evidence

```
$ curl -s https://chtozavino.ru/favicon.ico
data:image/gif;base64,R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7
$ curl -sI https://chtozavino.ru/favicon.ico | grep -i content-type
content-type: image/x-icon
```

The file and the string are not in this repository. The response has no `ETag` (Nitro static files have one). The source is most likely a Caddy rule in the deploy repository.

## Fix

1. Add a real `webui/public/favicon.ico` (16/32/48 px) made from `assets/product-logo-640x640.png`.
2. Remove the edge rule (deploy repository, owner).
3. Optional: `<link rel="icon" href="/favicon.ico" sizes="32x32">` next to the PNG/SVG link (SEO-002).

## Verify

`curl -s https://chtozavino.ru/favicon.ico | file -` → `MS Windows icon resource`; Yandex Webmaster «Диагностика сайта» shows no favicon problem.

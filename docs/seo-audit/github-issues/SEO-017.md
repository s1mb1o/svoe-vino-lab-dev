SEO-017: Get a field Core Web Vitals baseline (LCP, INP, CLS) before more performance work
<!-- labels: enhancement -->

**Priority:** P2 · **Effort:** M · **Status:** REQUIRES VERIFICATION

## Problem

There is no field data for the site. Performance work (SEO-002, SEO-003, SEO-004, SEO-021) is guided by lab runs only.

## Evidence

- The PageSpeed Insights API returned **429 RESOURCE_EXHAUSTED** for all anonymous calls on 2026-10-20. No CrUX, Search Console or RUM data was available to the audit.
- Lab only: Lighthouse 12.8.2 mobile, 2 runs per page, summary in `docs/seo-audit/github-issues/lighthouse-2026-10-20.json`. The audit machine had `benchmarkIndex` 660–1200, so TBT is overstated; byte weights and LCP elements are reliable. INP is not measurable in the lab.

## Fix

1. Search Console → «Основные интернет-показатели» (after SEO-020 registration) and PageSpeed Insights with an API key: record p75 LCP, INP, CLS by device, or record that there is not enough traffic.
2. Check what the existing Yandex Metrika counter (`webui/shared/metrika.ts`) already reports before adding anything.
3. Add a `web-vitals` client plugin only if no existing tool gives the data. Never send images, diary/account data or user-input URLs as telemetry.
4. Record a dated baseline (date, device, sample size) in `webui/ResearchLog.md`. Targets: p75 LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1 ([web.dev/vitals](https://web.dev/articles/vitals)).

## Verify

A dated baseline with sample counts exists, or a dated note says that field data is not available yet.

SEO-031: /shelf server HTML says «временно недоступен» when the recognition upstream is down; 2 s health check per SSR request
<!-- labels: bug -->

**Priority:** P2 · **Effort:** S · **Status:** VERIFIED in source, not observed on production

## Problem

`ScannerPage` fetches `/api/config` during SSR. `/api/config` checks the recognition upstream health on every request (timeout 2 s). If the check fails:

- the `/shelf` hero text changes to «Режим обработки полки временно недоступен.» and the page renders `ShelfUnavailable` («"Вся полка" временно недоступна»), with status 200. A crawler can index this text;
- every SSR response of `/`, `/shelf`, `/dish` waits up to 2 s.

On 2026-10-20 production returned `shelfAvailable: true`, so the bad state was not observed.

## Fix

1. Keep the descriptive hero text constant («Снимите полку целиком. Мы найдём бутылки и покажем совпадения.»). Show the unavailable notice in addition, not instead.
2. Cache the health result in `upstream-health.ts` for ≈30 s (module variable), so a slow upstream does not delay every SSR request.

## Verify

Start the built server with an unreachable `NUXT_PREDICTION_ENDPOINT`: `/shelf` HTML still contains the description; after the first request, responses take < 100 ms.

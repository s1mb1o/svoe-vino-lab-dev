SEO-004: Lazy-load result-only components on / and /shelf (WineExperiences, WineAlternatives)
<!-- labels: enhancement -->

**Priority:** P2 · **Effort:** S · **Status:** VERIFIED

## Problem

`WineExperiences` (with `WineLabelGuide`) and `WineAlternatives` render only after a recognition result. They are imported statically, so their chunks are `modulepreload` links in the first HTML of `/` and `/shelf`.

## Evidence

- `/_nuxt/BUN8dXRC.js` (91 KB raw, 26 KB gzip; components `WineExperiences`, `WineLabelGuide`) is preloaded on `/`.
- Lighthouse «Reduce unused JavaScript»: 36 KiB on each scanner page. On `/shelf` this chunk used 474 ms main-thread time (lab, slow machine).

## Where

[`webui/app/components/PhotoScanner.vue:119–120`](https://github.com/s1mb1o/svoe-vino-lab-dev/blob/cd8b063ecd000872567e543407b11926b45b3d37/webui/app/components/PhotoScanner.vue#L119-L120), [`webui/app/components/ShelfScanner.vue:95`](https://github.com/s1mb1o/svoe-vino-lab-dev/blob/cd8b063ecd000872567e543407b11926b45b3d37/webui/app/components/ShelfScanner.vue#L95).

## Fix

Use the Nuxt lazy prefix, as `ScannerPage.vue` already does for `LazyDinnerScanner`:

```vue
<LazyWineAlternatives v-if="hasResult && !mock && slug" … />
<LazyWineExperiences v-if="hasResult && wine" … />
```

## Side effects

The first result waits for one more chunk (≈26 KB gzip). The service worker precaches `_nuxt/**`, so offline use does not change.

## Verify

`npm run build && npm run test:bundle`; the HTML of `/` has no `modulepreload` for that chunk; `npm run test:label` and `npm run test:f04` pass.
